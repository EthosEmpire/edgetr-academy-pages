Private Keys

A private key is a secret number that authorises spending from a blockchain address. Whoever has the key controls the funds, and nobody can reset or reissue it.

  • 5 min read
  • Updated 21 November 2026

Why it matters

Every blockchain has to answer one question again and again: who is allowed to move these funds? There is no bank clerk checking identity and no company holding a password file. The answer is a private key, a secret number that a wallet stores and uses.

The rule that follows is short and has no exceptions. Whoever has the private key controls the funds. The network does not know or care who that person is.

How it works

A private key is a very large random number. In Bitcoin and Ethereum it is 256 bits long. From it the wallet calculates a public key, and from the public key an address. Both calculations are easy in one direction and not feasible in reverse with any known method, which is why an address can be published without exposing the key behind it. The Bitcoin version is described in keys and addresses.

When funds are sent, the wallet uses the private key to produce a digital signature for that exact transaction. Every computer on the network checks the signature against the public key. The private key itself is never sent anywhere. Signing transactions covers this step in detail.

In plain words

Think of a personal stamp that presses a seal into wax. Anyone can compare a seal with the pattern on public display and see that it is genuine. Nobody can carve the stamp by studying seals. And if a stranger gets hold of the stamp, every seal they press is as valid as the owner’s.

What a key can do

A private key is often compared with a password. The comparison hides the most important differences.

Password Private key
Who checks it One company’s server Every node on the network, by mathematics
If forgotten Usually reset by email or support Cannot be reset by anyone
If copied by a thief The company can lock the account The copy works for ever
Changing it Choose a new one for the same account Not possible. Funds must be moved to a different key

How large the number is

A 256-bit number has roughly 78 decimal digits. Guessing one specific key by trial is not a realistic threat. Real losses come from the key being copied or lost, not from it being guessed. The exceptions are keys made with poor randomness, such as a number chosen by a person or produced by faulty software.

Going deeper

Most people never see their keys. A modern wallet derives all its private keys from one seed phrase and handles them in the background. The seed phrase therefore needs at least the same protection as the keys.

Where a key lives. In a software wallet the key is stored on the phone or computer, normally encrypted. In a hardware wallet it stays inside a separate device. In a custodial account the company holds it and the user holds a login instead.

Exporting a key. Many wallets can display a private key as a string of 64 hexadecimal characters so that it can be imported elsewhere. Every place a key is displayed, typed, pasted or photographed is a place where it can be copied.

Security

No legitimate service, support agent or website ever asks for a private key or a seed phrase. The only place either is ever entered is the owner’s own wallet app or device, when the owner chooses to restore or import it. Never type one into a website and never photograph one. A request from anyone else is a theft attempt, however official it looks. edgeTR Academy never asks for one and has no wallet connection, login or payment anywhere on the site.

A hypothetical key in a screenshotHypothetical illustration

Tomas wants to move to a new wallet app. He exports a private key, takes a screenshot so that he can type it in later, and finishes the move. The screenshot stays in his photo library, which syncs to a cloud account protected by a password he also uses elsewhere.

Months later that password leaks from an unrelated website. Someone signs in to the cloud account, finds the image and imports the key into their own wallet. They sign a transaction sending the full balance to an address they control.

The network sees a valid signature and confirms it. Nothing was hacked on the blockchain, no alert was raised, and there is no party who can reverse the transfer.

What it does NOT mean

  • A private key is not a password. It cannot be reset, and no company stands behind it.
  • A private key is not tied to a person. The network verifies a signature, not an identity. It cannot tell an owner from a thief.
  • Sharing an address does not expose the key. Addresses and public keys are designed to be public.
  • A wallet PIN is not the key. Changing the PIN after a key has been copied changes nothing for the copy.
  • A key stored online is not hidden. Photos, notes, email drafts and cloud drives are among the first places an intruder searches.

Common mistakes

  1. Keeping a digital copy. Screenshots, note apps and messages to oneself turn a wallet secret into an ordinary file.
  2. Typing a key into a web page. Genuine sites do not need it. Pages that ask are described in phishing.
  3. Believing a helper needs it. Nobody can “check”, “verify” or “unlock” a wallet with a key except by taking control of it.
  4. Continuing to use an exposed key. Once a key may have been seen, the only remedy is moving the funds to a key that has never been exposed.

Risks and limitations

  • A single key is a single point of failure in both directions: loss locks the funds, and a copy gives them away.
  • Weak random number generation in software or devices has produced guessable keys in the past.
  • Key formats, signature schemes and account types differ between blockchains.
  • Nothing in the protocol provides for inheritance or emergencies. Access after death or illness depends entirely on arrangements made in advance.

Key takeaway

A private key is the one secret that authorises spending from an address. It cannot be reset, the network treats every holder of it as the owner, and no legitimate party ever asks to see it.
